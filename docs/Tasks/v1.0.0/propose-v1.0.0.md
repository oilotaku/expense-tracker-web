# Propose v1.0.0 — expense-tracker-web

> 格式定義：`HARNESS_HOME/rules/00-core/10-propose-tasks-fixed.md`（CORE-058）。填完跑 `/propose-to-tasks` 產 `tasks-v1.0.0.md`。

- **日期**：2026-09-03
- **狀態**：Draft

## 版本目標

做一個個人記帳網站的第一版，取代目前用 Numbers 手動記帳的方式，讓收支記錄、預算控管、資產總覽都能在同一個地方看到。

## In Scope

- 收入 / 支出交易輸入：日期、分類、明細、金額、收支類型、支付方式、帳戶（參考專案根目錄「記帳表單.nmbtemplate」的欄位設計）
- 分類可自訂標籤
- 週期性交易：可設定每月固定收入 / 支出，到期自動產生當月交易紀錄
- 預算設定：可設定當月 / 當日、各分類各自的預算上限
- 總資產 / 總負債總覽（現金帳戶加總 + 金融資產市值 − 負債）
- 金融資產輸入：
  - 股票：輸入股號 + 張數或股數（張／股換算），抓取即時市價（資料源：台股用證交所公開資訊）
  - 貴金屬：輸入品項 + 重量（兩／錢換算），抓取即時金價/銀價（資料源：專門貴金屬牌價網站，尚未選定具體來源）
- 多使用者帳號管理：註冊 / 登入，帳本各自獨立（不共享）

## Out of Scope

- 記帳以外的理財建議 / 投資分析
- 銀行帳戶自動同步（開放銀行 API）
- 帳本共享 / 多人協作記同一本帳（本版帳本各自獨立）
- 行動 App（本版只做 web）
- 多幣別（本版預設新台幣）

## 對外承諾

- REST API：`/api/v1/transactions`、`/api/v1/budgets`、`/api/v1/assets`、`/api/v1/auth`（實際路徑於拆 task 時定案）
- 股票 / 貴金屬報價可接受數分鐘延遲（非即時盤中），需快取以避免超過外部資料源速率限制
- 不同使用者之間的交易 / 預算 / 資產資料互相隔離

## 風險與相依

- 股票報價依賴證交所公開資訊 API 的實際可用性與速率限制，需在拆 task 前先做 spike 調查
- 貴金屬報價來源尚未選定具體網站，需先調查有無穩定 API，若只能爬蟲則有網站條款與穩定性風險
- 週期性交易在月底日期（如設定 31 號、遇到只有 30 天或 28/29 天的月份）需要明確補齊規則
- 報價快取建議依賴 Redis（`docker-compose.yml` 目前 `use_redis=false`，若確定要快取需回頭開啟）
